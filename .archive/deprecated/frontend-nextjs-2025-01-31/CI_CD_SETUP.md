# CI/CD Setup Guide

This document describes the CI/CD configuration for the Next.js frontend and how to set up required integrations.

---

## 📋 Overview

The frontend has **4 automated workflows** that run on every push and pull request:

1. **Frontend Quality Checks** (`ui-quality.yml`) - Linting, type checking, tests, bundle size
2. **Chromatic Visual Regression** (`chromatic.yml`) - Component visual testing
3. **Lighthouse CI** (`lighthouse-ci.yml`) - Performance and accessibility audits
4. **Standard GitHub Actions** - Build verification

---

## 🔧 Required Secrets

To enable all workflows, configure the following secrets in GitHub repository settings:

### 1. Chromatic Project Token

**Purpose**: Enables visual regression testing for Storybook components

**Setup Steps**:
1. Go to [chromatic.com](https://www.chromatic.com/)
2. Sign in with your GitHub account
3. Create a new project for `ninaivalaigal/frontend-nextjs`
4. Copy the project token
5. Add to GitHub: **Settings → Secrets → Actions → New repository secret**
   - Name: `CHROMATIC_PROJECT_TOKEN`
   - Value: `<your-project-token>`

**Workflow**: `.github/workflows/chromatic.yml`

**Commands**:
```bash
# Local testing
npm run chromatic

# Or with token
CHROMATIC_PROJECT_TOKEN=<token> npm run chromatic
```

---

### 2. Lighthouse CI GitHub App Token (Optional)

**Purpose**: Enables Lighthouse CI to comment on PRs with performance metrics

**Setup Steps**:
1. Install the Lighthouse CI GitHub App:
   - Go to [github.com/apps/lighthouse-ci](https://github.com/apps/lighthouse-ci)
   - Click "Configure"
   - Select your repository
   - Grant permissions
2. The app will automatically generate a token
3. Add to GitHub: **Settings → Secrets → Actions → New repository secret**
   - Name: `LHCI_GITHUB_APP_TOKEN`
   - Value: `<auto-generated-token>`

**Note**: Lighthouse CI will still run without this token, but won't comment on PRs.

**Workflow**: `.github/workflows/lighthouse-ci.yml`

## 🚀 Workflows

### 1. Frontend Quality Checks (`ui-quality.yml`)

**Triggers**:
- Push to `main` or `develop`
- Pull requests to `main` or `develop`
- Changes to `frontend-nextjs/**`

**Jobs**:
- **ESLint**: Code linting with auto-fix suggestions
- **TypeScript**: Type checking
- **Jest Tests**: Unit tests with 80% coverage threshold
- **Bundle Size**: Verifies bundle stays under 500KB
- **Storybook Build**: Ensures Storybook builds successfully

**Local Commands**:
```bash
npm run lint              # Run ESLint
npm run lint:fix          # Auto-fix ESLint issues
npm run type-check        # TypeScript check
npm run test              # Run tests
npm run test:coverage     # Tests with coverage
npm run build             # Production build
npm run build-storybook   # Build Storybook
```

---

### 2. Chromatic Visual Regression (`chromatic.yml`)

**Triggers**:
- Push to `main`
- Pull requests
- Changes to `frontend-nextjs/src/**` or `frontend-nextjs/.storybook/**`

**What It Does**:
- Builds Storybook
- Captures snapshots of all components
- Compares against baseline
- Detects visual changes
- Auto-accepts changes on `main` branch

**Features**:
- ✅ Component isolation testing
- ✅ Cross-browser testing
- ✅ Visual diff detection
- ✅ Review UI in Chromatic dashboard

**Local Testing**:
```bash
npm run storybook         # View components locally
npm run chromatic         # Run Chromatic manually
```

---

### 3. Lighthouse CI (`lighthouse-ci.yml`)

**Triggers**:
- Push to `main` or `develop`
- Pull requests
- Changes to `frontend-nextjs/**`
- Manual workflow dispatch

**Jobs**:
- **Desktop Audit**: Performance, accessibility, best practices, SEO
- **Mobile Audit**: Same metrics on mobile viewport

**Thresholds** (enforced):
- Performance: ≥ 90
- Accessibility: = 100
- Best Practices: ≥ 90
- SEO: ≥ 90

**What It Does**:
- Builds production bundle
- Starts Next.js server
- Runs Lighthouse audits
- Comments results on PRs (if app token configured)
- Uploads detailed reports as artifacts

**Local Testing**:
```bash
npm run build
npm run start
# In another terminal:
npx @lhci/cli@0.12.x autorun
```

## 🐛 Troubleshooting

### Workflow Fails: "Secret not found"
**Solution**: Add the required secret in GitHub repository settings

### Chromatic: "Project token invalid"
**Solution**:
1. Regenerate token in Chromatic dashboard
2. Update `CHROMATIC_PROJECT_TOKEN` secret in GitHub

### Lighthouse: "Failed to start server"
**Solution**:
1. Ensure `npm run build` succeeds locally
2. Check for port conflicts (default: 3000)
3. Review build logs in workflow

### ESLint: "Too many errors"
**Solution**:
```bash
npm run lint:fix  # Auto-fix issues
npm run lint      # Check remaining issues
```

### TypeScript: "Type errors"
**Solution**:
```bash
npm run type-check  # See all errors
# Fix errors in your IDE or manually
```

### Tests: "Coverage below threshold"
**Solution**:
```bash
npm run test:coverage  # See coverage report
# Add tests for uncovered code
```

## 🔄 Updating Workflows

To modify CI/CD workflows:

1. Edit workflow files in `.github/workflows/`
2. Test changes on a feature branch
3. Verify workflows run successfully
4. Merge to `main`

**Key Files**:
- `ui-quality.yml` - Linting, tests, builds
- `chromatic.yml` - Visual regression
- `lighthouse-ci.yml` - Performance audits

## 📝 Best Practices

### For Developers
1. **Run checks locally before pushing**
   ```bash
   npm run lint
   npm run type-check
   npm run test
   ```

2. **Review Chromatic diffs** before accepting changes

3. **Monitor Lighthouse scores** and address regressions

4. **Keep bundle size small** - review bundle analyzer reports

### For Maintainers
1. **Review workflow runs** regularly
2. **Update dependencies** in workflows (Node.js versions, actions)
3. **Monitor secret expiration** (especially GitHub App tokens)
4. **Adjust thresholds** as needed (coverage, bundle size, Lighthouse)
