# Governance Reports

**Purpose**: All completion reports, status summaries, and governance-related reports.

## 📋 What Goes Here

### ✅ Completion Reports
- User story completion reports: `US{ID}_COMPLETION.md`
- Implementation status reports: `US{ID}_IMPLEMENTATION_STATUS.md`
- Progress reports: `US{ID}_PROGRESS_REPORT.md`
- Refactoring completion: `SPEC_{ID}_{ID}_REFACTORING_COMPLETE.md`

### ✅ Status & Health Reports
- SPEC status reports: `SPEC_STATUS_MONTHLY_YYYY-MM.md`
- SPEC audit reports: `SPEC_AUDIT_COMPLETE_SUMMARY.md`
- Governance automation: `SPEC_GOVERNANCE_AUTOMATION_COMPLETE.md`

### ✅ Developer Work Summaries
- Developer completion summaries: `DEVELOPER_{LETTER}_FINAL_SUMMARY.md`
- Work summaries: `DEVELOPER_{LETTER}_WORK_SUMMARY.md`

### ✅ Test & Validation Reports
- Test result summaries: `TEST_RESULTS_*.md`
- Validation reports: `*_VALIDATION_COMPLETE.md`

## 🚫 What Does NOT Go Here

- ❌ SPEC analysis documents → `docs/spec-analysis/`
- ❌ Technical guides → `docs/guides/` or `docs/`
- ❌ Architecture docs → `docs/architecture/`
- ❌ Security docs → `docs/security/`
- ❌ Task assignments → `tasks/active/`

## 📝 Naming Conventions

- Completion reports: `US{ID}_COMPLETION.md`
- Status reports: `{TOPIC}_STATUS.md`
- Implementation: `{TOPIC}_IMPLEMENTATION_STATUS.md`
- Test results: `TEST_RESULTS_{TOPIC}.md`

See [docs/DOCUMENT_ORGANIZATION.md](../docs/DOCUMENT_ORGANIZATION.md) for full rules.
